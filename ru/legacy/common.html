Классические общие параметры и независимые среды¶

Классическое обнаружение объектов использует ATSLegacy 2.7.0; классическая классификация использует ATSLegacy 2.5.0. Они идентифицируют версии архитектуры/конфигурации, а не версии современной архитектуры. На страницах используются некоторые элементы управления, но реализуют предварительную обработку набора данных и картографирование параметров отдельно.

Порядок применения настроек¶

Загрузите выбранную модель YAML и ее базовые конфигурации, сгенерируйте отдельную конфигурацию эксперимента, затем примените явные перезагрузки пользовательского интерфейса. Встроенные файлы YAML не переписываются. Используйте конфигурацию, сохраняющую исходную настройку, а не универсальный фиксированный по умолчанию.

Эпохи, размер партии и случайное семя используют значения пользовательского интерфейса напрямую, по умолчанию для 100, 4 и 42 соответственно; другие настройки оптимизации по умолчанию для конфигурации модели. Каждый эксперимент сохраняет effective_det.yaml или effective_clas.yaml Z для проверки фактических размеров, путей передачи данных, классов, скорости обучения и настроек загрузчика.

Используйте местные предварительно подготовленные весы Укажите совместимый .pdparams для инициализации в этом забеге. Это не переключатель для подготовки резюме.
Случайная инициализация Не загружайте предварительно подготовленные веса конфигурации; начинайте со случайных параметров. По-прежнему требуется действительная конфигурация модели.

Встроенные предустановки обнаружения автоматически используют пакетные весы; SOD и l совместно используют один и тот же файл. Предустановки классификации по умолчанию не позволяют проводить предварительную подготовку. Для ее использования выберите локальные предварительно подготовленные веса и выберите соответствующую модель из каталога в комплекте. Каталог установки можно перемещать; весы не зависят от кэша разработчика.

Скорость обучения и оптимизатор¶

Первоначальная скорость обучения UI значение 0 означает использовать конфигурацию; он не устанавливает скорость обучения двигателя для 0Заполнитель конфигурации Use также не делает переопределение.

Держите настроенный оптимизатор или явно выберите Momentum, SGD, Adam или AdamW. Приложение адаптирует структуры параметров при переключении; AdamW получает численный распад веса, а не словарь регуляризатора предыдущего оптимизатора.

Аугментация данных и AMP¶

Сохраняя модель увеличения сохраняет свою первоначальную политику. Отключение случайного увеличения заменяет предварительную обработку проверки для случайного увеличения обучения. Нормализация, расположение канала и требуемое изменение размера остаются.

Для AMP можно использовать настройки модели, отключить или включить режим явно. Явное включение требует GPU. При обучении на CPU AMP отключается. Если выбран режим по конфигурации, фактическое использование AMP на GPU задаёт модель.

Загрузка данных и выбор GPU в Windows¶

Нативная многопроцессорная загрузка данных ограничена в классическом времени выполнения Windows. При workers>0 это приложение использует потоки внутри изолированного процесса для параллельного чтения и предварительной обработки; 0 сохраняет исходный загрузчик. Начните с 2 или 4; большее значение не обязательно быстрее.

Каждая задача использует один выбранный графический процессор NVIDIA; можно выбрать любую установленную карту, но не поддерживается нативное совместное обучение одной классической модели с несколькими графическими процессорами Windows. Независимый процесс обычно сообщает о графическом процессоре 0 из-за отображения видимого устройства; это не означает, что физический выбор карты был проигнорирован.

Для каждого запуска создаётся отдельный каталог с отметкой времени. Обучение и автоматический экспорт выполняются в независимой классической среде. Допустимые диапазоны указаны в справочнике параметров.
