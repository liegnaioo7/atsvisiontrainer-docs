Rilevamento classico di oggetti 2.7.0¶

Per il rilevamento standard di oggetti. L'elenco mostra s / m / l / x / sod; SOD richiama la configurazione effettiva per oggetti piccoli, non una semplice riduzione delle dimensioni di un modello ordinario.

Addestrare da una sola cartella COCO¶

Selezionare una cartella COCO e fare clic su Controlla dataset per verificare classi e numero di immagini di addestramento e validazione. Il software genera la configurazione dati nell'esperimento; non occorre modificare manualmente il file integrato coco_detection.

Le immagini OK senza riquadri partecipano come campioni negativi di sfondo. Senza validazione separata, tutti i campioni di addestramento vengono mantenuti: nessuna suddivisione automatica, validazione o mAP. Loss e tasso di apprendimento restano visibili; non è un errore di addestramento.

L'opzione avanzata Usa configurazione dati YAML mantiene le impostazioni dati del modello; l'utente deve verificare percorsi e classi. I percorsi relativi sono risolti dalla directory di lavoro del rilevamento classico, non automaticamente dalla directory di uno YAML esterno arbitrario.

Altezza e larghezza: tre modalità¶

Modalità delle dimensioni Addestramento Validazione, test ed esportazione
Usa le dimensioni del modello Mantieni la configurazione di riferimento, incluso l'addestramento multiscala Mantieni la configurazione di riferimento
Dimensioni fisse Usa altezza × larghezza specificate e disattiva le dimensioni casuali Usa la stessa altezza × larghezza
Personalizza solo le dimensioni di validazione ed esportazione Mantieni la strategia originale delle dimensioni di addestramento Usa altezza × larghezza specificate

Inserire altezza e larghezza separatamente; entrambe devono essere 96–8192 e multiple di 32. Le dimensioni personalizzate ridimensionano direttamente l'immagine senza mantenere il rapporto d'aspetto originale.

Con altezza 320 e larghezza 640, scegliere la terza modalità per riprodurre la sola modifica di eval_height=320 e eval_width=640. L'addestramento può ancora scegliere dimensioni quadrate dalla configurazione originale: non diventa 320×640. Scegliere la seconda modalità per fissare anche l'addestramento a quel rettangolo.

Se si disattivano anche gli aumenti casuali, la preelaborazione di addestramento cambia di conseguenza; la modalità dimensioni non riattiva gli aumenti disattivati.

Metriche di validazione¶

Con un set di validazione indipendente, la valutazione segue l'intervallo della configurazione del modello; non sono garantite metriche a ogni epoca. I grafici mostrano risultati effettivi del rilevamento come mAP50-95, mAP50 e mAP75. L'accuratezza di classificazione non è una metrica generale di rilevamento di questa pagina.

Assenza del set di validazione, validazione non ancora prevista e validazione senza risultati validi sono stati distinti, segnalati separatamente nei grafici. I valori mancanti non vengono sostituiti con 0; uno 0 effettivamente calcolato viene mantenuto.

Esportazione automatica¶

Dopo l'addestramento viene selezionato automaticamente un checkpoint salvato ed eseguita l'esportazione ufficiale per inferenza. Dopo il successo, export/export_det dell'esperimento contiene generalmente:

model.pdmodel
model.pdiparams
model.pdiparams.info
infer_cfg.yml

Il log di esportazione indica il percorso effettivo. infer_cfg.yml contiene preelaborazione e classi reali; le dimensioni personalizzate si riflettono negli input esportati. L'esportazione usa la CPU anche se l'addestramento ha usato la GPU.

Per ottimizzatori, caricamento e inizializzazione vedere i parametri classici comuni; tutti i controlli sono nella tabella del rilevamento.

Valutazione sul set di addestramento¶

Deselezionato per impostazione predefinita. In modalità COCO, questa opzione valuta tutte le immagini e annotazioni di addestramento al posto di un set di validazione separato, senza suddivisione automatica né modifiche ai dati originali. Viene usato il set di addestramento anche se è disponibile un set di validazione separato. L’opzione è disabilitata quando si usano le impostazioni del dataset YAML.

AP/mAP sul set di addestramento riflette solo l’adattamento a quei dati e non misura la generalizzazione a nuove immagini. La valutazione segue l’intervallo della configurazione del modello. I log originali conservano il miglior AP; i grafici e le metriche storiche indicano la provenienza dei dati di valutazione.
