Подготовка наборов данных¶

Современное обнаружение объектов, сегментация экземпляров и OBB¶

Выберите корень набора данных, содержащий data.yaml; ориентированная страница обнаружения также принимает путь YAML. YAML определяет обучение, валидацию и отображение классов. Изображения и метки должны соответствовать; идентификаторы классов начинаются с 0 и соответствуют списку классов.

dataset/
  data.yaml
  images/train/
  images/val/
  labels/train/
  labels/val/
Задание Содержание этикетки: один объект на строку
Стандартное обнаружение class_id center_x center_y width height
Сегментация по этапам class_id x1 y1 x2 y2 …Контурный многоугольник объекта
Ориентированное обнаружение объектов class_id x1 y1 x2 y2 x3 y3 x4 y4Четыре угла

Нормализуйте координаты до 0 1. Углы OBB должны работать по часовой стрелке или против часовой стрелки. Обычные пятиколонные коробки, необработанные ярлыки DOTA и самопересекающиеся четырехугольники не являются действительными входными данными OBB. Программное обеспечение проверяет ярлыки и сообщает номера файлов и строк.

Современные классификации¶

Организовать обучение/проверку изображений по классам, используя соответствующие названия подпапок в качестве названий классов. Рекомендуются явные папки train/class_name и val/class_name; механизм классификации считывает их по своим правилам набора данных. Эта страница не импортирует классические списки классификации TXT.

classification/
  train/OK/...
  train/NG/...
  val/OK/...
  val/NG/...

Результаты классификации записываются рядом с набором данных в dataset-name_runs, предотвращая обработку результатов как класса. Держите старые папки результатов вне каталогов классов.

Классическое обнаружение объектов: одна папка COCO¶

Режим COCO выбирается по умолчанию. Выберите корень набора данных и щелкните Контрольный набор данных. Программное обеспечение распознает обучающие изображения, COCO JSON, классы и дополнительный независимый набор проверки. Типичным макетом является:

coco/
  images/train/...
  Изображения/val/... #опционально
  annotations/train.json
  аннотации/val.json # optional

Без независимого набора валидации все обучающие изображения используются для обучения, без автоматического расщепления или расчета mAP. ОК фоновые изображения могут не иметь коробок: вести свои записи изображений без изготовления записей в annotations или создания класса объектов OK. Программное обеспечение сохраняет эти отрицательные образцы.

Картирование классов основано на аннотациях обучения; имена классов обучения и проверки должны совпадать. Программное обеспечение создает копии аннотаций и список классов внутри эксперимента без изменения исходных файлов COCO.

Классическая классификация из одной папки¶

Сначала прочитайте train_list.txt, val_list.txt и Label.txt; без списков выявите train/class_name и val/class_name. Сохраните существующий раскол без автоматического разделения. Идентификаторы классов должны быть смежными, а классы проверки должны принадлежать классам обучения.

Для других соглашений об именах папок сначала запустите набор данных Check и проверьте распознанные числа и классы. Не изобретайте идентификаторы классов, чтобы обойти проверку.

Обнаружение аномалий по изображениям OK и отдельная калибровка¶

Включите в учебный каталог только ОК-изображения. Независимая ОК-калибровочная директория является необязательной; если пустая, примерно 20% удерживается после дедупликации на основе контента, требующей, по крайней мере, 3 отдельных ОК-изображений. Калибровочные изображения исключаются из банка памяти; дубликаты контента между обучением и калибровкой отвергаются.

Это правило автоматического удержания применяется только к обнаружению аномалий, а не к классическому обнаружению COCO.
