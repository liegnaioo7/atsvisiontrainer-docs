Preparazione dei dataset¶

Rilevamento oggetti, segmentazione di istanze e rilevamento orientato moderni¶

Selezionare la radice del dataset contenente data.yaml; la pagina del rilevamento orientato accetta anche un percorso YAML. Lo YAML specifica addestramento, validazione e mappatura delle classi. Immagini ed etichette devono corrispondere; gli ID iniziano da 0 e coincidono con l'elenco delle classi.

dataset/
  data.yaml
  images/train/
  images/val/
  labels/train/
  labels/val/
Attività Contenuto delle etichette: un oggetto per riga
Rilevamento standard id_classe centro_x centro_y larghezza altezza
Segmentazione di istanze id_classe x1 y1 x2 y2 …, poligono del contorno dell'oggetto
Rilevamento di oggetti orientati id_classe x1 y1 x2 y2 x3 y3 x4 y4, quattro vertici

Normalizzare le coordinate tra 0 e 1. I vertici OBB devono seguire senso orario o antiorario. Riquadri ordinari a cinque colonne, annotazioni DOTA grezze e quadrilateri autointersecanti non sono input OBB validi. Il software verifica le annotazioni indicando file e riga.

Classificazione moderna¶

Organizzare le immagini di addestramento e validazione per classe, usando i nomi delle sottocartelle come nomi di classe. Si consigliano cartelle esplicite train/nome_classe e val/nome_classe, lette dal motore di classificazione secondo le proprie regole. Questa pagina non importa gli elenchi TXT della classificazione classica.

classification/
  train/OK/...
  train/NG/...
  val/OK/...
  val/NG/...

I risultati di classificazione sono salvati accanto al dataset in nome-dataset_runs, evitando che siano riconosciuti come classe. Non inserire vecchi risultati nelle cartelle delle classi.

Rilevamento classico di oggetti: una cartella COCO¶

La modalità COCO è selezionata per impostazione predefinita. Scegliere la radice del dataset e fare clic su Controlla dataset. Il software riconosce immagini di addestramento, JSON COCO, classi ed eventuale set di validazione indipendente. Struttura tipica:

coco/
  images/train/...
  images/val/...             # facoltativo
  annotations/train.json
  annotations/val.json      # facoltativo

Senza un set di validazione indipendente, tutte le immagini sono usate per addestrare, senza suddivisione automatica né calcolo di mAP. Le immagini OK di sfondo possono non avere riquadri: conservarne i record senza inventare elementi in annotations o creare una classe oggetto OK. Il software mantiene questi campioni negativi.

La mappatura delle classi si basa sulle annotazioni di addestramento; i nomi delle classi di addestramento e validazione devono coincidere. Il software genera copie delle annotazioni e un elenco delle classi nell'esperimento senza modificare i file COCO originali.

Classificazione classica: una cartella di dataset¶

Legge prima train_list.txt, val_list.txt e Label.txt; senza elenchi riconosce train/nome_classe e val/nome_classe. Conserva la suddivisione esistente senza ricrearla. Gli ID delle classi devono essere consecutivi e le classi di validazione devono essere presenti nell'addestramento.

Con strutture o nomi diversi, eseguire prima Verifica dataset e controllare conteggi e classi riconosciuti. Non inventare ID per aggirare i controlli.

Rilevamento anomalie: immagini OK e calibrazione indipendente¶

Inserire solo immagini OK nella directory di addestramento. La directory indipendente di calibrazione OK è facoltativa; se vuota, viene riservato circa il 20% dopo la deduplicazione per contenuto, con almeno 3 immagini OK distinte. Le immagini di calibrazione sono escluse dalla banca; i duplicati di contenuto tra addestramento e calibrazione sono rifiutati.

Questa regola di suddivisione automatica vale solo per il rilevamento anomalie, non per il rilevamento COCO classico.
