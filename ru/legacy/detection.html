Классическое обнаружение объектов 2.7.0¶

Для стандартного обнаружения объектов. Список моделей показывает s / m / l / x / sod; SOD использует фактическую конфигурацию модели малого объекта, а не просто меньший размер входа для обычной модели.

Обучение из одной папки COCO¶

Выберите папку COCO и нажмите «Проверить набор данных», чтобы проверить классы и количество изображений для обучения / валидации. Программное обеспечение генерирует конфигурацию данных в эксперименте; вручную редактирование встроенного coco_detection Файл не нужен.

Неразмеченные изображения OK используются как отрицательные фоновые примеры. При отсутствии отдельного набора валидации все изображения идут на обучение. Автоматического разделения, валидации и расчёта mAP нет. Потери и скорость обучения продолжают отображаться.

Опция конфигурации набора данных Advanced Use YAML сохраняет настройки набора данных файла модели; пользователи должны обеспечить правильные пути и классы.Относительные пути разрешаются из классического рабочего каталога обнаружения, а не автоматически из произвольного внешнего каталога YAML.

Высота и ширина: три режима¶

Режим размера Подготовка Проверка, тестирование и экспорт
Используйте параметры размера модели Сохранение эталонной конфигурации, включая многомасштабное обучение Сохранить исходную конфигурацию
фиксированный размер Используйте указанную высоту × ширину и отключите выбор случайных размеров Используйте ту же высоту × ширину
Настройка валидации и только размер экспорта Сохранить оригинальную стратегию размера обучения Используйте указанную высоту × ширину

Введите высоту и ширину отдельно; оба должны быть 96–8192 и многократно 32Пользовательские размеры напрямую изменяют размер изображения без сохранения исходного соотношения сторон.

Для высоты 320 и ширины 640 выберите третий режим для воспроизведения, изменяя только eval_height=320 и eval_width=640. Обучение может по-прежнему случайным образом выбирать квадратные размеры из исходной конфигурации; оно не становится 320×640. Выберите второй режим, если обучение также должно использовать этот фиксированный прямоугольник.

Если случайное увеличение также отключено, обучение предварительной обработки изменяется соответственно; режим размера не включает повторное увеличение отключенного.

Метрики валидации¶

При независимом наборе валидации оценка выполняется с интервалом валидации конфигурации модели; метрики не гарантируются каждую эпоху. На диаграммах показаны фактические результаты оценки обнаружения, такие как mAP50-95, mAP50 и mAP75. Точность классификации не является общей метрикой обнаружения на этой странице.

Нет набора валидации, валидация еще не назначена, а валидация без действительных результатов - это разные состояния, показанные отдельно на графиках. Недостающие значения не заполнены 0; фактически вычисленный 0 сохраняется.

Автоматический экспорт¶

После обучения автоматически выбирается сохраненный контрольный пункт и запускается официальный экспорт выводов.После успеха export/export_det в эксперименте обычно содержит:

model.pdmodel
model.pdiparams
model.pdiparams.info
infer_cfg.yml

Завершенный экспортом журнал дает реальный путь. infer_cfg.yml хранит эффективную предварительную обработку и классы; пользовательские размеры отражаются в экспортируемых входах и предварительной обработке. Экспорт работает на процессоре даже при обучении с использованием графического процессора.

Настройки оптимизатора, загрузки данных и инициализации описаны в разделе общих параметров классических архитектур. Полный перечень приведён в таблице параметров обнаружения.

Использование обучающего набора для валидации¶

В режиме COCO выбор этой опции оценивает все обучающие изображения и аннотации вместо отдельного набора валидации, без автоматического разделения или изменения исходных данных. Данные обучения используются даже при наличии отдельного набора валидации. Эта опция отключена при использовании настроек набора данных YAML.

AP/mAP на обучающем наборе отражает только соответствие этим данным и не измеряет обобщение новых изображений. Оценка следует за интервалом в конфигурации модели. Сырьевые журналы сохраняют лучшую информацию AP; диаграммы и исторические метрики идентифицируют источник данных оценки.
