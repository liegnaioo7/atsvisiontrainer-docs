環境とよくある質問¶

完全パッケージで保持するもの¶

実行ファイル、_internal、クラシック環境、異常検出環境を含むソフトウェアフォルダー全体を配布してください。動作する GPU ドライバーと対応システムランタイムが必要です。同梱フレームワークは NVIDIA ドライバーの代わりにはなりません。

MkDocs は開発時の文書生成にのみ使用します。利用者が MkDocs、Python、別の Web サーバーをインストールする必要はありません。ソフトウェアがローカルマシンだけで利用できる軽量サービスを起動し、5 言語のページと検索リソースを同梱します。

同梱ヘルプは _internal/help_site にあり、ヘルプ機能に必要です。ルートの docs 技術説明と package-manifest.json は学習・推論の実行依存ではありません。manifest はファイル整合性の調査用です。

mAP が表示されない理由¶

まず独立検証セットの有無、次に検証エポックへの到達を確認します。学習セットだけのクラシック COCO は分割も検証も行いません。検証したのに有効な値がなければ元の検証ログを確認し、loss を代わりにしないでください。

GPU 使用率が低い¶

GPU 使用率はタスク、バッチサイズ、画像サイズ、データ読み込み、CPU 前処理、測定間隔に左右されます。GPU 使用率と GPU メモリ使用量は別の指標です。ログで GPU 実行と data_cost の割合を確認し、Windows のクラシック学習では workers を適度に調整して実際の処理速度を比較してください。

RAM または GPU メモリ不足¶

まず batch を減らし、次にタスクに応じて画像サイズを下げます。異常検出では候補特徴数、コアセット上限、保持率も下げられます。タスクによって意味が異なり、コアセット上限は batch ではありません。

クラシックモデルが事前学習済み重みをダウンロードしている¶

設定内の事前学習指定を使うと、その URL に従います。利用者のマシンにキャッシュがあるとは限りません。オフラインでは互換性のあるローカル重みかランダム初期化を選択してください。構造ファイルがあっても、事前学習済み重みのキャッシュがあるとは限りません。

重み・クラス・前処理の不一致¶

重みと同じタスク、設定、クラス順序、前処理を使用してください。クラシックモデルは実験設定を取り込めます。モダン分類では前処理メタデータを保持します。水平枠検出器を OBB として使ったり、エクスポートしたクラシック静的モデルを .pdparams チェックポイントとして扱ったりしないでください。

ONNX が CPU で実行される理由¶

現在、メインの推論ページではモダン ONNX を CPU で実行する互換性方針を適用し、その旨を生ログに表示します。GPU を選択してもこの方針は変わりません。

ヘルプページまたは検索を開けない¶

ソフトウェアを開いたままサイドバーからヘルプを再表示し、既定のブラウザーとローカル権限を確認してください。インターネットは不要です。ファイル不足なら help_site を含む完全な新パッケージを使用します。ソースへの文書追加だけでは旧パッケージは更新されません。
